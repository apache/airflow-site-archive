.. py:function:: build_pod_label_selector(job)

   Return the label selector of the pods of the Job, built from its ``spec.selector``.

   Kubernetes adds the ``batch.kubernetes.io/job-name`` label to the pods only without ``manualSelector``,
   while ``spec.selector`` matches them in both modes.


.. py:function:: build_job_event(job, xcom_results)

   Build the event of a finished Job, as passed to ``KubernetesStartKueueJobOperator.execute_complete``.

   :param job: the finished Job.
   :param xcom_results: the raw XComs read from the pods, by pod name.


.. py:function:: get_succeeded_pod_xcoms(pods, xcom_results)

   Return the XComs read from the pods that succeeded, skipping failed and preempted pods.


.. py:function:: list_job_pods(client, namespace, label_selector, job_uid)

   Return the pods the Job has now: those matched by ``build_pod_label_selector`` that the Job owns.

   With ``manualSelector``, the selector may also match the pods of other Jobs, such as the same task
   in another Dag run; the Job controller tells them apart by owner too.


.. py:function:: is_pod_deleted(client, pod)

   Return whether the pod no longer exists.


.. py:function:: collect_xcom_results(client, pod_manager, job, base_container_name, xcom_results)

   Read into ``xcom_results`` the XCom of each pod of the Job whose base container has ended.

   Reading the XCom also stops the XCom sidecar: until then the pod, and so the Job, cannot finish.
   Pods already read are skipped, so this is called at each poll.


.. py:class:: KubernetesKueueJobTrigger(job_name, job_namespace, base_container_name, kubernetes_conn_id = None, poll_interval = 10.0, cluster_context = None, config_file = None, in_cluster = None, do_xcom_push = False)

   Bases: :py:obj:`airflow.triggers.base.BaseTrigger`


   Wait until a Job run through Kueue is finished, even if Kueue preempts it several times.

   Unlike :class:`~airflow.providers.cncf.kubernetes.triggers.job.KubernetesJobTrigger`, it polls the Job
   rather than the pods found when the Job started, and reads the XComs from the pods the Job has at
   each poll.

   :param job_name: The name of the job.
   :param job_namespace: The namespace of the job.
   :param base_container_name: The name of the base container in the pod.
   :param kubernetes_conn_id: The :ref:`kubernetes connection id <howto/connection:kubernetes>`
       for the Kubernetes cluster.
   :param cluster_context: Context that points to kubernetes cluster.
   :param config_file: Path to kubeconfig file.
   :param poll_interval: Polling period in seconds to check for the status.
   :param in_cluster: run kubernetes client with in_cluster configuration.
   :param do_xcom_push: If True, the content of the file
       /airflow/xcom/return.json in the container will also be pushed to an
       XCom when the container completes.
